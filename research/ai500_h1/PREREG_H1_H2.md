# AI500 榜单前向超额收益 H1 / H2 —— 预注册

**冻结时间**：2026-09-25（本文件的 commit 早于任何前向收益数据的拉取与计算）
**用户拍板**：2026-09-25（"2. 做"，采纳上一轮提出的窗口 / 基准 / 判据）
**性质**：确认性检验。**同一数据先探索后确认，证据强度打折**——P1–P8 以及 09-25 的核对已经看过这批信号的入场前涨幅（prior_gain）分布，但**没有看过任何信号的前向收益**。

---

## 1. 要回答的问题

- **H1**：AI500 score 榜的信号在**首次上榜**之后，是否跑赢同期币安 USDT 永续全市场？
- **H2**：score 分档（<60 / 60–70 / 70–80 / ≥80）对前向超额收益有没有区分度？特别是：V3 的 ≥80 门槛有没有信息量？

这两个问题问的是**信号**，不是 V3 的交易规则（出场、止损都不参与）。

## 2. 事件定义

- **数据**：`user_data/ai500_score_history_v3.csv`（服务器导出，09-05 06:32 → 09-24 05:30 UTC，每 5 分钟一次的按时点快照）。
- **信号**：`(symbol, start_time)`。
- **H1 事件时刻 t0** = 该信号**第一次出现在快照中**的时刻。采集开始后 1h 内就已在榜的信号（入榜时刻未知）**剔除**。
- **入场**：t0 之后第一根 1h K 的开盘价（t0 向上取整到整点，防止用到未来数据）。
- **前向窗口 H** ∈ {1d, 4d, 7d}，**主判据为 4d**。离场 = 入场后第 H 小时那根 1h K 的开盘价。K 线覆盖不到完整窗口的事件，在该窗口下剔除（右删失）。
- **收益**：简单收益，不扣费用（信号层面的检验）。

## 3. 基准

- **宇宙 U**：`exchangeInfo`（2026-09-25 快照，已存档到 `data/`）里所有 `contractType=PERPETUAL` 且 `quoteAsset=USDT` 的合约，**包括 SETTLING（已下架）**；剔除 V3 配置黑名单（股票代币、PAXG/XAUT/NATGAS、BTCDOM、UP/DOWN/BULL/BEAR）。
- **基准收益** = 同一个 [入场, 入场+H] 区间内，U 中两端都有 1h K 的全部合约的收益**中位数**。
- **超额** = 信号收益 − 基准收益。

## 4. 统计量与区间

- **主统计量**：事件超额收益的**中位数**（同时报告均值和事件数 n）。
- **CI**：按**入场日（UTC）区块自举**，��天整天地有放回重抽，5000 次，报告 90% CI（5%/95% 分位）和**实际**的中位数超额。
- **功效（在看事件收益之前先算）**：伪事件 = 从 U 里随机抽 symbol × 从同一时间窗里随机抽入场整点，数量等于真实事件数；按同一套日区块自举，重复 200 组，得到零效应下中位数超额的 sd。**MDE ≈ 2.49 × sd**（α=0.10 双侧，power=0.8）。

## 5. 判据（冻结）

| 结果 | 结论 |
|---|---|
| 4d 中位数超额 ≤ 0 | **H1 不成立：没有 alpha 证据** → 支持关闭 V3（用户已决定关闭，本检验决定**后续方向**） |
| 4d 中位数超额 > 0 且 CI 下界 > 0 | 有方向性证据：榜单早期信号可能有超额，值得另立"首次上榜入场"方向（新 TASK，重新预注册） |
| 4d 中位数超额 > 0 但 CI 跨零 | ⭕ 不能排除零效应；按 MDE 写"无 ≥MDE 量级的效应" |
| CI 上界 < 0 | 有反向证据：上榜之后跑输市场 |

1d / 7d 只作为稳健性报告，不能推翻 4d 的结论。

## 6. H2 定义

- 对每个信号、每个分档：**该信号的 score 第一次落入该档**时，就是一个事件（入场规则同 §2）。
- 统计量：每档的 4d 中位数超额，以及 **≥80 档 − <80 各档合并** 的中位数差，用日区块自举算 90% CI。
- **事先声明**：19 天内 ≥80 的信号只有约 6 个，**H2 在设计上几乎不可能给出结论**，只作描述性报告，不得据此改门槛。
- **附带描述（H1b）**：对达到 ≥80 的信号，配对列出"首次上榜入场"和"首次 ≥80 入场"两种入场各自的 4d 超额。这回答的是"V3 的亏损来自榜单本身，还是来自门槛把入场推迟了"。只做描述，不做推断。

## 7. 已知局限（事先写明）

1. 窗口只有 19 天，基本是单一市场状态；事件在时间上高度重叠，有效 n ≈ 天数量级，而不是事件数。
2. 截至 09-24 仍在榜的信号，在 7d 窗口下大多被删失。
3. 基准用的是"当前 exchangeInfo 里有的合约"。它包含已下架的（SETTLING），但**不包含**在 exchangeInfo 里已经完全消失的合约（如果有）。
4. 零结果的解读以 MDE 为边界，不能写成"榜单无效"。
