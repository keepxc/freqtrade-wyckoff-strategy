# 出场规则模拟：把 48h 改成 72h 会怎样（2026-09-25）

> ⚠️ **探索性**。n≤13 个 ≥80 episode（20 天数据），含死相位样本，止损用 15m 低点近似，未含滑点分布。
> **禁止作为上线依据**；任何规则改动属 B 类，需重新预注册。
> 数据源：币安合约真实 K 线（15m 做止损精度 / 4h / 1d 做判定）+ `ai500_score_history_v3.csv` + `ai500_local/score_*.csv`
> 脚本：`scripts/simulate_exit_rules.py`（v2，含校验与配对分析）

## 0. 直接回答：**改 72h = 零影响**（这次可以判死，不是"判不了"）

配对分析（同一 episode、同一入场，逐笔差值）：**均值差 +0.04pp、中位差 0.00pp、90% CI [−1.0, +1.1]**。

原因：**12 笔里没有一笔触及 48h 上限**（平均持仓 **4.1 小时**，出场分布 `{4h阴线: 5, stop: 7}`）。
上限从未"绑定"⇒ 48 → 72 → 168h 都不改变任何一笔的结果。**"把持仓上限改大"这个方向可以从清单上划掉。**

## 2. 机制解读（三条）

1. **4h 阴线判定在噪声级别反复触发**：它是"切掉未走完的信号"的主凶——去掉它（②）或改成日线（④），
   累计从 **−41.0% 翻到 +28~32%**。均持仓从 4.1h 拉长到 21~23h，正好对上"信号在 +24h/+48h 才付钱"。
2. **胜率仍然只有 8~17%，收益全靠 2 笔大赢家**（②④ 的 median 仍是 −5.6%，10/12 笔被 −5% 止损吃掉）。
   ⇒ V3 的真实结构 = **低胜率 + 尾部驱动**；而现行两条出场规则（4h 阴线 + −5% 止损）**同时**在砍尾部。
3. **但不能因此取消止损**：⑧ 累计 +159.5% 的代价是**单笔最差 −87.6%**（AIN 真实崩盘，已交叉验证非数据问题：
   榜上价 0.1806 / K 线 0.1857 在入场点一致，崩盘发生在 bot 用 −5.2% 止损离场之后）。
   杠杆永续上这是**归零风险** ⇒ 按"风险检查优先"原则直接否决。
4. **放宽止损也不等于更好**：⑤（−10%）反而更差（−20.5%），因为把 AIN/BULLA 这类崩盘亏满。
   ⇒ 正确方向不是"更宽"，而是**让止损宽度与波动/信号周期匹配**（BR 单根 4h σ=7.46%，−5% ≈ 0.67σ = 落在噪声内；
   可用 σ/ATR 自适应，或改用"日线收盘破位"替代盘中固定百分比）。

## 3. 模拟器可信度（校验）

用 bot 实际成交做对照：入场价偏差 **−2.4% ~ +6.3%**（多数 ±2.5%，差异来自"我在 4h 边界用 15m 收盘、bot 秒级后成交"）；
**出场复现：9 笔 stop_loss 全部命中；#4 实盘 +18.03% ↔ 模拟 +19.76%；#10 实盘 +5.60% ↔ 模拟 +4.78%**。

## 4. 数据完整性教训（本轮踩到的坑，必须记住）

- ⚠️ **`fetched_at_utc` 列名骗人**：两份 score 文件的时间戳**值都是 +08:00（CST）**，只有列名一个叫 utc 一个叫 cst。
  v1 模拟把它当 UTC 解析 ⇒ K 线查找**整整偏 8 小时** ⇒ 出现"K 线与榜上价格差 14~38%"的假象（BR/IOST）。
  **正确做法：一律 `datetime.fromisoformat(s).astimezone(ZoneInfo('Asia/Shanghai'))`。**
- 一度怀疑 AIN 的 −87% 是数据错误 → 用**第三方权威（bot 实际成交价）**与**独立数据源（榜上价）**双向交叉验证，
  确认是真实崩盘。⇒ 遇到极端值时，先做交叉验证再下结论，不轻易归因给数据。

## 5. 建议

1. **不做"48h → 72h"**（零影响，已判死）。
2. 真正值得实验的是**出场口径**：候选 = ①4h 阴线判定去掉/改日线；②止损改波动自适应（σ/ATR）而非固定 −5%；
   ③保留强制止损（AIN 教训）。
3. 这些都需要**预注册 + 更长样本**：除"零影响"那条外 n=12 判不了。建议按 TASK 131 的 J1–J5 句式写判据，
   并用 shadow 并行臂验证（不替换现行规则、不污染归因）。
4. 模拟器已入库为常备工具：`research/ai500_h1/scripts/simulate_exit_rules.py`。
