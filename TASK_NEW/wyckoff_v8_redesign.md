## 核心设计原则

### V7 的失败教训（必须写入设计约束）

1. **1H 图无法承载威科夫结构**：SC/BC 在 1H 图上物理上无法可靠识别（FTX 崩盘期间 1H 最大宽幅仅 0.87x ATR）
2. **PNF 目标位与动量退出不能共存**：两套哲学互相竞争退出权，down_wave 永远先触发
3. **因果律需要结构支撑**：没有明确的 Phase 判断，任何"持有到目标位"的设计都会被动量信号推翻
4. **参数调优无法解决架构问题**：axis_mult 从 1.0 调到 1.2 结果完全一样，根本路径不通
5. **纯靠成交量和 ATR 识别 SC/BC 会误报**：必须加入相对价格位置约束

### V8 设计约束（已拍板，不可在实现中绕过）

- 日线图做结构判断，1H 图只做执行
- PNF 目标位是**退出机制**，不只是入场过滤器
- 每一层职责单一，不跨层决策
- 动量退出（down_wave）降级为预警，不作为主退出机制
- SC 识别必须包含"价格已回撤至值得积累的位置"这一前提
- Shadow Protect 是 trailing 机制，不是 partial take-profit
- **所有日线信号基于 T-1 日收盘，1H 执行层在 T 日使用，一天滞后是设计的一部分**

### D-004：Swing Low 识别算法

| 项目 | 决策 |
|------|------|
| 算法 | 固定窗口分形（非 Zigzag，非复杂算法） |
| 窗口 | window = 10（前后各 10 个交易日，约 1 个月局部低点） |
| 定义 | 候选点 i 的 low < 前 10 日所有 low，且 < 后 10 日所有 low |

```python
def is_swing_low(df, i, window=10):
    if i < window or i >= len(df) - window:
        return False
    left  = df['low'].iloc[i-window:i]
    right = df['low'].iloc[i+1:i+window+1]
    return df['low'].iloc[i] < left.min() and df['low'].iloc[i] < right.min()
```

| 误报处理 | 2018-02 的 6000 低点 vs 2018-12 的 3122：由条件5的 Fibonacci 约束自动区分——2018-02 跌幅相对前期涨幅不够深，不满足"回撤 > 上涨 50%"的约束 |

### D-005：Phase 回退逻辑

| Phase 转换 | 触发条件 | 说明 |
|-----------|---------|------|
| Phase D → B | 日线收盘 < TR 中线，连续 3 日 | 单日不算，需持续性 |

### 1.1 两阶段结构

```
阶段1：Exhaustion Zone（耗尽区）
├── 时间窗口：1 ~ 5 个交易日
├── 允许多日累积（2018 慢熊磨底需要 3 天，2020 恐慌只需 1 天）
├── 表示供给力量逐步耗尽的区域
├── 🔴 Zone 冻结规则（防漂移，必须锁定）：
│   ├── Zone 是"事件区间"，不是"滑动窗口"
│   ├── 一旦进入 exhaustion（score > threshold）：
│   │   zone_start = t  ← 冻结起点
│   │   zone_high_close = max(close[zone_start : t])  ← 累积更新
│   │   zone_low = min(low[zone_start : t])            ← 累积更新
│   ├── 一旦 exhaustion 结束（score ≤ threshold）：
│   │   zone 闭合，zone_high_close / zone_low 锁死，不再更新
│   └── 一旦 confirm 触发 → SC 确认 → zone 生命周期结束
└── 输出：zone_low（锁定）、zone_high_close（锁定）

阶段2：Confirmation Bar（确认K线）— 双通道确认（V8.3 最终版）
├── zone_high_close = exhaustion_zone 锁死后的最高收盘价
├── 🔴 双通道设计（防止慢反转漏信号）：
│   │
│   ├── 强确认（恐慌反转，量价齐升）：
│   │   strong_confirm = close > zone_high_close AND close_pct > 2.5%
│   │   适用：2020-03(+16.2%), 2022-11(+10.5%)
│   │
│   ├── 弱确认（慢反转/震荡反转，结构突破但动量温和）：
│   │   weak_confirm = close > zone_high_close AND close > open
│   │   适用：2018-12 慢熊磨底后温和反弹, 2022-06 震荡结构
│   │
│   └── 最终判定：confirm = strong_confirm OR weak_confirm
│
├── 设计理由：
│   ├── 成交量已在 exhaustion 评分阶段（C3）完成验证
│   ├── 纯 close_pct > 2.5% 会在慢反转中漏信号（2018 确认K +8.67% 刚好过线，
```

### 1.3 Exhaustion Score 评分模型（核心）

```
exhaustion_score = w1 × 趋势强度 + w2 × 成交量异常 + w3 × 波动扩张 + w4 × 位置约束

判定：exhaustion_score > threshold → 进入 Exhaustion Zone
```

#### 1.3.1 评分项定义

**C1：趋势强度（双模式，max 聚合）**

```
C1 = max(
  过去 60 日收盘跌幅 / X_60,   ← 慢熊模式
  过去 3 日收盘跌幅 / X_3       ← 急崩模式
)
目的：覆盖 2018（慢熊16%）和 2022-11（急崩，20日跌幅仅 -2.6%）

X_60 待定（第二组参数，从 P0 锚点反推）
X_3  待定（第二组参数，从 P0 锚点反推）
```

**C2：新低突破（硬条件，不在评分模型内）**

```
条件：当日 low < 过去 252 日最低 low（一年新低标准）
作用：必须先满足 C2，才启动 exhaustion 评分计算
C2 不参与评分，是进入 exhaustion 计算的前置硬条件
```

**C3：成交量异常（多日聚合，max 聚合）**

```
C3 = max(
  当日 volume / 20日均量 / V,      ← 单日量比
  3日累计 volume / (3×20日均量) / V  ← 3日累计量比
) / V

V 待定（第二组参数，从 P0 锚点反推）
```

**C4：波动扩张（多日聚合，max 聚合）**

```
C4 = max(
  当日 (high - low) / ATR_14 / A,    ← 单日宽幅
  3日累计 (high - low) / ATR_14 / A   ← 3日累计宽幅
) / A

A 待定（第二组参数，从 P0 锚点反推）
```

**C5：位置约束（降级为评分项，不再硬条件）**

```
C5 = 0.5 × 回撤比例得分 + 0.5 × swing_low 偏差得分

回撤比例得分 = min(1.0, 从60日高点回撤比例 / R)
  R 待定（第三组参数，用误报率校准）

swing_low 偏差得分 = max(0, 1.0 - |当前low - swing_low| / swing_low / B)
  swing_low 识别：固定窗口分形，window=10（见 D-004）
  B 待定（第三组参数，用误报率校准）
```

#### 1.3.2 权重与阈值

```
weight 方向（固定，不作为调优参数）：
├── w1 = 0.35（趋势强度：最重要，没有趋势就没有积累，SC 存在的前提）
├── w2 = 0.25（成交量异常：供应高潮的标志）
├── w3 = 0.25（波动扩张：气候性行动的确认）
└── w4 = 0.15（位置约束：过滤器，不是信号源，降权防止过约束）

threshold 方向（唯一调节旋钮）：
├── 搜索范围：threshold ∈ [0.5 ~ 0.7]
├── 初始设定：threshold = 0.6
├── 含义：不需要所有条件都完美满足，总分及格即可
└── 调优策略：先用 0.6 跑全量回测，看检出分布（目标 1~3次/年），
    过多则提 threshold，过少则降 threshold

核心原则（防过拟合）：
├── 权重固定不动 → 4个P0样本无法支撑5维参数空间
├── threshold 单参数调节 → 从"参数拟合"变为"模型结构验证"
└── 若 threshold 降到 0.5 还是漏 P0 锚点 → 模型结构有问题，不是参数问题
```

### 1.4 最终 SC 判定流程（V8.3 最终版：zone 冻结 + 双通道确认）

```
对日线每根K线，按序执行：

Step 0：前置硬条件
  if 当日 low >= 过去 252 日最低 low:
    → 不进入 exhaustion 计算，跳过

Step 1：Exhaustion 评分（C1/C3/C4/C5）
  exhaustion_score = w1×C1 + w2×C3 + w3×C4 + w4×C5
  if exhaustion_score < threshold:
    if zone 处于活跃状态:
      → zone 闭合，zone_high_close / zone_low 锁死
    → 跳过

Step 2：Zone 生命周期管理（🔴 冻结规则）
  if zone 未激活 AND exhaustion_score ≥ threshold:
    → zone_start = t（冻结起点）
    → zone_high_close = close[t]
    → zone_low = low[t]
    → zone 状态 = 活跃

  if zone 已激活 AND exhaustion_score ≥ threshold:
    → zone_high_close = max(zone_high_close, close[t])  ← 累积更新
    → zone_low = min(zone_low, low[t])                  ← 累积更新
    → zone 持续延伸（最大 5 日）

Step 3：Zone 闭合
  if zone 已激活 AND exhaustion_score < threshold:
    → zone 闭合，zone_high_close / zone_low 锁死
    → zone 不再接受新K线，等待 confirmation

Step 4：Confirmation 判定（🔴 双通道）
  if zone 已闭合（锁死状态）:
    对之后每根K线检查：
    
    strong_confirm = close > zone_high_close AND close_pct > 0.025
    weak_confirm   = close > zone_high_close AND close > open
    
    if strong_confirm OR weak_confirm:
      → SC 确认！记录 SC 日期 = confirm_bar 日期
      → SC 低点 = zone_low（已锁死）
      → zone 生命周期结束（去重：同一 zone 只确认一次）
      → confirm 类型标记：strong / weak（用于后续分析）

Step 5：超时处理
  if zone 闭合后 10 日内无 confirm:
    → zone 作废，视为"假 exhaustion"
    → 等待下一个 C2 触发重新开始
  if exhaustion_zone 闭合后 10 日内无 confirm_bar:
    → zone 作废，视为"假 exhaustion"
    → 等待下一个 C2 触发重新开始
```

**SC 类型标记**（用于后续分析，不影响判定逻辑）:

| 类型 | 特征 | 例子 |
|------|------|------|
| 慢速耗尽型 | zone ≥ 3 日，无极端量/宽幅 | 2018-12 |
| 恐慌释放型 | zone 1-2 日，量比 > 2x | 2020-03, 2022-11 |
| 标准耗尽型 | zone 1-3 日，量比 1.5-3x | 2022-06 |

### 1.5 BC 识别（对称设计，方向相反）

BC 的两阶段模型与 SC 对称，方向相反：

```
阶段1：Euphoria Zone（狂热区）
├── C1：过去60日涨幅 > X% OR 过去3日涨幅 > Y%
├── C2：当日 high > 过去252日最高 high（硬条件）
├── C3/C4：成交量/宽幅条件同 SC（方向相反）
├── C5：当前价格 > 60日最低点 × (1+R%)
└── 输出：zone_high（狂热区最高点）、zone_low_close（狂热区最低收盘价）

阶段2：Distribution Confirmation Bar（派发确认K）
├── close < zone_low_close（收盘价跌破狂热区最低收盘价）
└── AND close_pct < -2.5%（价格动量确认，对称 SC）
```

BC 参数在 SC 参数校准完成后用对称值填入，不独立校准。BC 锚点（2021-11 高点、2022-03 反弹顶）用于单独验证。

```
├── 价格到达 target_1：保护地板上移至 entry_price + 0.5%
├── 价格到达 target_2：保护地板上移至 target_1
├── 价格到达 target_3：保护地板上移至 target_2 × 0.95
├── 价格从历史最高点回撤 > Y%：触发退出
│   Y 待定（TASK 5 中用数据校准）
└── 优先级覆盖：日线 Phase 改变时强制退出
    （结构判断优先于任何 trailing 状态）

设计原则：
├── Trailing 而非 partial take-profit
│   原因：P&F 目标位是完整上涨目标，
│         在目标位前分批退出违背因果律
└── Phase 改变强制退出不可绕过
    原因：结构性信号比价格回撤信号更可靠
```

### 3.3 目标位锁定时机

```
锁定时机：Phase C 开始时（Spring 触发时）
原因：此时 TR 边界已完全确定，P&F 计算有稳定输入

特殊情况：
├── Phase C 失败（Spring 失败回退 Phase A）→ 目标位作废
├── Phase D 直接跳过 Phase C → 在 Phase D 进入时锁定
└── 目标位一旦锁定，Phase D/E 期间不重新计算
```

## 阶段回溯：从退出机制到指标定义溯源（2026-05-07）

### 背景

V8 退出机制优化尝试了三个方向，全部受阻。根本原因不在退出逻辑本身，而在上游信号和过滤器定义——每个指标在定义时都隐含了假设，当这些假设相互冲突时，下游优化无从下手。

---

### 实验记录

#### 实验 1：down_wave 退出时机诊断

**脚本**: `analyze_down_wave_exit_timing.py`  
**数据**: 199 笔 axis_support + down_wave 退出

| 指标 | 值 |
|------|-----|
| 退出后 10 根K线下跌比例 | **77.9%** |
| 退出后上涨比例 | 22.1% |

**结论**: down_wave 方向判断正确（78% 胜率），问题不在退出逻辑本身，而在退出时机太早（中位数 +1.43%）。

#### 实验 2：MIN_PROFIT 利润门槛

**改动**: 在 `custom_exit` 中加 `current_profit >= WY_DW_MIN_PROFIT` 门控  
**测试值**: 0.0（基线）/ 0.02 / 0.03

**结果**: 三次回测数据几乎无差异。  
**根因**: down_wave 同时存在于两条路径——`exit_signal`（向量化，line 3674）和 `custom_exit`（逐笔，line 5878）。Freqtrade 先检查 `exit_signal`，触发即退出，`custom_exit` 的利润门控永远等不到。

**结论**: 信号路径无法承载 per-trade 条件。利润门槛方案被否决。

#### 实验 3：Phase D 与 wave_start 关系诊断

**脚本**: `diagnose_wave_start_phase.py`  
**假设**: 日线 Phase D 上下文可提升 wave_start 入场频率（从 ~36笔/年 → ~55笔/年）

**发现**:

| Phase | 天数 | 占比 | wave_start 笔数 |
|-------|------|------|:---:|
| A | 11 | 0.5% | 0 |
| B | 144 | 5.9% | 0 |
| C | **0** | **0.0%** | **0** |
| D | 90 | 3.7% | 1 |
| E | 1208 | 49.8% | 133 |
| unknown | 975 | 40.2% | 7 |

**结论**: Phase D 仅占 3.7% 时间窗，天花板太低。Phase C 从未触发（Spring 条件太苛刻）。94% 的 wave_start 已在 Phase E 中，瓶颈不在 Phase。

#### 实验 4：Phase 检测器参数调优

**改动**: `phase_detector.py`
- `spring_max_days`: 3 → 7
- B→D 量能门槛: 1.2x → 移除
- C→D 量能门槛: 1.5x → 移除
- E→D 确认天数: 2 → 1

**结果**:

| 指标 | 改前 | 改后 |
|------|------|------|
| Phase D 天数 | 90 (3.7%) | 127 (5.2%) |
| Phase C 天数 | 0 | 0 |
| Phase D wave_start | 1 笔 | 2 笔 |

**结论**: 参数调整后 Phase D 增长 41%，但对 wave_start 增量贡献仅 +1 笔。Phase 状态机本身的结构性限制（TR 锁定、E→D 回退难、C 从不触发）比参数更根本。

#### 实验 5：wave_start 过滤器漏斗分析

**脚本**: 策略内嵌计数器，输出到 `ws_filter_diag.txt`  
**方法**: 对 wave_start_entry 的 6 个条件逐级计数拦截数

```
漏斗: raw=709 → final=244 (通过率 34.4%)
```

| 过滤器 | 拦截数 | 拦截率 |
|--------|:---:|:---:|
| raw 信号 | 709 | - |
| ❌ **bull_market** (close>ema200) | **465** | **65.6%** |
| wyckoff_context_ok | 0 | 0% |
| harmony_ok | 0 | 0% |
| no_sot_warning | 0 | 0% |
| quality_ok | 0 | 0% |
| ✅ final | 244 | 34.4% |

**发现**: `bull_market` 一个条件拦截了 65.6% 的信号。其他四个 Wyckoff 条件拦截率全为 0——一旦过 EMA200，全过。EMA200 是静态滞后指标，正在物理性地阉割 wave_start 的因果发现能力。

#### 实验 6：移除 bull_market（wave_start 专用）

**改动**: `wave_start_entry` 移除 `bull_market` 条件，依赖 V8 Phase 过滤器（C/D/E）兜底  
**注意**: 非纯净 A/B 对比（baseline 含其他差异）

| 指标 | Baseline | 移除 bull_market |
|------|:---:|:---:|
| wave_start 交易数 | 141 | 146 (+5) |
| wave_start 胜率 | 97.2% | 97.3% |
| wave_start 均利润 | +3.18% | +3.13% |
| wave_start 净利润 | 103,306 | 170,394 (+65%) |
| TSL 触发 | 17 | 5 |

**问题**: wave_start 仅增加 5 笔（而非理想中的 200+），因为 `final_entry` 层仍有 V8 Phase 过滤（仅 C/D/E）、`pnf_target_valid_long`、`rr_long_ok` 等多层拦截。

### 核心洞察：所有问题最终指向同一个根源

经过 6 个实验、3 个方向的尝试，一个共同的模式浮现：

```
exit 优化  → 被信号路径绕过  → 回到信号定义
Phase 调整 → 时间窗太窄      → 回到 Phase 定义
过滤器诊断 → EMA200 拦截 65%  → 回到 bull_market 定义
移除过滤器 → 被其他层拦截    → 回到 final_entry 定义
```

**每一个下游优化都被上游定义的隐含假设所限制。** 在继续任何优化之前，必须从源头逐一审查每个关键指标的定义：

### 需要回溯定义的指标清单

| 序号 | 指标 | 当前定义 | 问题 | 位置 |
|:---:|------|------|------|------|

### 实验 A：wave_start 豁免 composite_intent=distributing 拦截

**改动**（固化到 `WyckoffV7_TrueMethod.py`）:

```python
# V8 固化：wave_start 豁免 distributing 拦截，保留 trending_down 拦截
# 依据：distributing 是滞后标签，wave_start ChoCh 动能已经反转，语义矛盾
```

## 实验记录：Wave_start K 线形态过滤（2026-05-23，已证伪）

**背景**：V8 上线后第一笔干跑交易（Trade ID 1，BTC/USDT Long @ 77866，2026-05-21 18:00）止损宽达 -21.29%（TR Low ~61295）。入场信号由 17:00 一根上影线（H=78064，close=77831）触发，日线已连续 8 天下跌，是典型的单根 wick 假突破。

**诊断结论**：wave_start 对入场 K 线形态没有任何约束，触发后不区分"实体阳线突破"和"上影线刺穿后回落"。

**实验内容**：在 `entry_detector.py` 中加入 K 线质量过滤（`v8_body_ok`），共测试两个方案：

| 方案 | 实现 | 交易数 | 总收益 | 结论 |
|------|------|--------|--------|------|
| S-7 基线（无过滤） | — | 471 | $1,806,104 | 基准 |
| 方案 A-v1：body_ratio≥0.5 @ 当前 bar | `(close-low)/(high-low)≥0.5` | 314 | $261,571 | 时序错位：shift 后的信号 bar 不是突破 bar |
| 方案 A-v2：close>open @ wave_start 原始 bar | `wave_start_bullish` shift 对齐 | 42 | $6,956 | 物理冲突：wave_start 标记转折点，该 bar 本身多为阴线 |

**根本性障碍**：

1. **时序错位**：`is_wave_start` 经过 `shift(min_bars)` 后，信号 bar 是 N+lag，不是原始突破 bar N。在 N+lag 上做形态过滤，过滤的是与突破无关的后续 K 线。

2. **物理冲突**：WaveAnalyzer 的 `wave_start` 标记下行波的转折低点。该转折 bar 本身在统计上大概率是阴线或十字星（价格在该 bar 仍在下跌，下一根才反弹），`close > open` 通过率极低（~9%）。

**最终决策**：回退至 S-7 基线，接受该风险。

- 干跑 Trade ID 1 是统计上的低概率正常信号，不代表系统性缺陷
- 历史 4 年回测（2022-2026）中，TR Low 止损从未被触发，最差亏损单均由 `v8_down_wave` 退出（最差 -5.19%）
- 用 K 线形态过滤 wave_start 与 WaveAnalyzer 信号生成机制天然冲突，**此路不通**

**根因**：死猫反弹将参考高点向下更新，后续的跌幅比例被人为缩小。

**根因**：重置阈值（close > EMA200，无缓冲）粒度过细，等价于无熊市记忆。

## TASK 17 — BE 路径分层门控与结构化重置（2026-06-03）

### 背景：Logic Bug 定位

**法医审计数据**（2026-06-03，基于本地 1D 数据）：

- `be_zone_high_locked = $82,828.7`（2026-05-06 高点，BE 触发锚点）
- 2026-05-08 ~ 05-12：BTC 连续5日收盘 > EMA200（~80,846），触发旧重置逻辑 → `be_dcs_active = False`
- 关键事实：5日内 BTC **最高仅到 82,460**（05-10），**从未突破 82,828.7**
- 结果：be_dcs 被时间阈值抹除，05-22 跌破 EMA200 后无法恢复 → 83k→67k 第二波零空单

**违反原则**：分发之"因"被时间稀释（5日 EMA200 阈值），而非结构证伪（突破供应上限），违反威科夫因果律。

### Wyckoff 物理依据

在威科夫体系中，一个派发周期的"因"只能由两种事件证伪：
1. **价格放量突破供应上限**（close > be_zone_high_locked）→ 大机构筹码被更强力量承接
2. **新积累周期开始**（新 BC/SC 出现）→ 旧分发之因已兑现完毕，能量释放

EMA200 是趋势参考，无法从物理上"抹除"大机构在 $82.8k 留下的供应筹码。

### 方案：两层分离

| 层级 | 变量 | 语义 | 重置条件 |
|------|------|------|----------|
| **结构因（Active）** | `be_dcs_active` | 分发之因是否存续 | close > `be_zone_high_locked` 或 新 BC |
| **战术门（Gated）** | `be_ema200_above_streak >= 5` | 是否暂停入场 | close < EMA200（立即重开） |

```
dcs_arr[i] = dcs_active OR (be_dcs_active AND NOT be_dcs_gated)
```

- `be_zone_high_v`：从 df 预读（Step 3 已计算）

### 威科夫物理学背景

**Fall Through the Ice（FTI，跌破冰层）** 是威科夫在 *The Richard D. Wyckoff Method* 中定义的标志性空头确认事件：

> 价格跌破横盘区间的下沿支撑（冰线/Ice Line），随后反弹回测冰线，但反弹失败（无需求）并再度下行——此时的卖空是位置（结构下方）与动力学（需求匮乏）的双重确权。

**FTI 与已有路径的本质区别**：
- SOW/BE/LPSY：依赖 PNF 因果结构 + EMA200 持续税
- ICE_LPSY：EMA200 本身作为冰线，触碰失败
- REDIST：中期横盘 + 高点递降（7日结构性供应补充）
- **FTI（新）**：区间支撑破位 + 回抽失败（位置确权优先于EMA200距离）

FTI 是 Markdown 早期最肥美的入场点：此时整个左侧派发结构已经清晰，冰线从支撑变阻力，操作风险远低于博弈崩盘首日。

**冰层物理厚度**：冰线要成为大机构认可的"供应主导区"，需要价格在 EMA200 下方持续足够长的时间，形成真实的分发结构。persist < 20 天 = 浮筹，不构成冰层。

**诊断证据**（TASK 23 审计）：

| 集群 | MSOW 日 | persist（策略内`_persist_days`） | 7D结果 | 风险定性 |
|------|---------|:---:|------|---------|
| 2024-07-04 | raw=1天 | 0（未激活）| BTC反弹至65k | ❌ 牛市短暂跌破 |
| 2025-11-04 | raw=2天 | 0（未激活）| 小幅回升 | ❌ 早期跌破无确权 |
| 2023-03-09 | raw=2天 | 0（未激活）| -18.6% 灾难性 | ❌ 最高风险案例 |
| 2026-01-20 | raw=79天 | ~65 | 持续下跌至75k | ✅ 结构性熊市 |

### 实现

在 `WyckoffV8.py` 日线 FTI MSOW 计算中加入一行：

```python
# TASK 24: persist >= 20 确认税（_persist_days = ema200_persist激活后的连续天数）
# raw=1/2 → _persist_days=0（未激活），自动过滤
# raw=79 → _persist_days≈65（通过）
_fti_persist = pd.Series(_persist_days, index=df_1d.index).shift(1).fillna(0)

_fti_msow_raw = (
    _fti_consol_shifted &
    (_fti_persist >= 20) &          # ← TASK 24 新增
    (df_1d['close'] < _fti_ema200_shifted) &
    ...
)
```

**变量语义**：`_persist_days` 是 `ema200_persist`（连续15天跌穿 EMA200 后激活）激活后的累计天数。`_persist_days=0` 表示系统从未进入 ema200_persist 状态，即 raw 持续天数 < 15。故 `_persist_days >= 20` 实际对应 raw≥34 天，远严于"20天原始计数"——但对于过滤 raw=1/2 的假信号完全有效。

## TASK 27：wave_breakdown 趋势跟随空头第八路径（2026-06-06）✅ +40,697pp

### 立项依据

**观察**：BTC 从 82k 跌至 60k（-26%），V8 全程零空单。根因是 V8 所有 7 条空头路径均依赖先验结构（SOW/UTAD/BE/LPSY/ICE_LPSY/REDIST/FTI），在纯趋势下行无结构触发的场景下存在"动量盲区"。

**关键事实**：max_open_trades=2 已是基线配置，但 4 年 509 笔交易中双槽同时占用时长为 0 小时，第二槽从未被使用。wave_breakdown 空头可占用第二槽，与多头共存，消除槽位竞争的顾虑。

**46% 冲突分析**：2022 年熊市 28 笔多头中 13 笔（46%）在局部下跌趋势中入场，wave_breakdown 理论上可能阻断。但 max_open_trades=2 使两者可以并存，实际影响需回测量化。

### 设计决策

| 维度 | 决策 | 物理依据 |
|------|------|---------|
| 入场信号 | `is_wave_start & wave_direction=='down'` | ChoCh 摆高确认 + 下降浪启动，与多头对称 |
| 熊市门控 | `daily_ema200_persist & persist_days>=15` | 复用 TASK 14 已固化值，避免引入新参数 |
| 动量过滤 | `wave_efficiency>0.001 & wave_displacement>close*0.008` | 效率门槛与多头对称；位移 0.8% 与 down_wave 退出阈值一致 |
| PNF 门控 | 豁免 `pnf_valid_short` 和 `rr_short_ok` | 趋势跟随无 PNF 目标位约束，同 REDIST/ICE_LPSY |
| 止损 | 入场 bar 的 `wb_swing_high_ref × 1.01` | Swing high 被突破 = 下跌结构失效 |
| 退出 | `v8_up_wave_reverse`（现有路径） | 上升波 ChoCh 出现 = 反转结构，对称退出 |
| 优先级 | WB < FTI（最低） | 新路径保守放置，不干扰高优先级已验证路径 |

**新增参数：零个**。所有阈值复用现有固化值。

### 实现细节（Code Review 修复）

**止损锚点漂移 Bug**：初始实现从 `last`（当前 bar）读 `wb_swing_high_ref`，随行情推进 ffill 会漂移到新（更低）摆高，导致止损悄悄收紧。

**修复**：在 `custom_stoploss` 中按 `trade.open_date` 定位入场 bar index，从入场 bar 读锚点，永久固化：

```python
open_date = pd.Timestamp(trade.open_date).tz_convert(None)
entry_idx = int(df_dates.searchsorted(open_date, side='right')) - 1
wb_sl = dataframe.iloc[entry_idx].get('wb_swing_high_ref', np.nan)
```
