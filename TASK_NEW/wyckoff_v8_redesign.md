## 核心设计原则

### V7 的失败教训（必须写入设计约束）

1. **1H 图无法承载威科夫结构**：SC/BC 在 1H 图上物理上无法可靠识别（FTX 崩盘期间 1H 最大宽幅仅 0.87x ATR）
2. **PNF 目标位与动量退出不能共存**：两套哲学互相竞争退出权，down_wave 永远先触发
3. **因果律需要结构支撑**：没有明确的 Phase 判断，任何"持有到目标位"的设计都会被动量信号推翻
4. **参数调优无法解决架构问题**：axis_mult 从 1.0 调到 1.2 结果完全一样，根本路径不通
5. **纯靠成交量和 ATR 识别 SC/BC 会误报**：必须加入相对价格位置约束

### V8 设计约束（已拍板，不可在实现中绕过）

- 日线图做结构判断，1H 图只做执行
- PNF 目标位是**退出机制**，不只是入场过滤器
- 每一层职责单一，不跨层决策
- 动量退出（down_wave）降级为预警，不作为主退出机制
- SC 识别必须包含"价格已回撤至值得积累的位置"这一前提
- Shadow Protect 是 trailing 机制，不是 partial take-profit
- **所有日线信号基于 T-1 日收盘，1H 执行层在 T 日使用，一天滞后是设计的一部分**

| 结构性滞后 | V8 的所有日线信号（SC/BC、Phase、TR 边界、P&F 目标位）基于 T-1 日收盘，1H 执行层在 T 日才能使用 |
| 定性 | 此滞后是**设计的一部分，不是 bug**，任何版本中不得绕过 |

```python
# 标准实现模板（所有涉及日线数据的地方必须遵循此模式）
def populate_indicators(self, dataframe, metadata):
    informative = self.dp.get_pair_dataframe(metadata['pair'], '1d')
    informative = informative.shift(1)  # ← 必须在任何计算之前
    informative = self._detect_sc_bc(informative)   # SC/BC 在 shift 后运行
    informative = self._detect_phase(informative)    # Phase 在 shift 后运行
    dataframe = merge_informative_pair(
        dataframe, informative, self.timeframe, '1d', ffill=True
    )
    return dataframe
```

### D-004：Swing Low 识别算法

| 项目 | 决策 |
|------|------|
| 算法 | 固定窗口分形（非 Zigzag，非复杂算法） |
| 窗口 | window = 10（前后各 10 个交易日，约 1 个月局部低点） |
| 定义 | 候选点 i 的 low < 前 10 日所有 low，且 < 后 10 日所有 low |

```python
def is_swing_low(df, i, window=10):
    if i < window or i >= len(df) - window:
        return False
    left  = df['low'].iloc[i-window:i]
    right = df['low'].iloc[i+1:i+window+1]
    return df['low'].iloc[i] < left.min() and df['low'].iloc[i] < right.min()
```

| 误报处理 | 2018-02 的 6000 低点 vs 2018-12 的 3122：由条件5的 Fibonacci 约束自动区分——2018-02 跌幅相对前期涨幅不够深，不满足"回撤 > 上涨 50%"的约束 |

### 1.1 两阶段结构

```

├── 允许多日累积（2018 慢熊磨底需要 3 天，2020 恐慌只需 1 天）

├── 🔴 Zone 冻结规则（防漂移，必须锁定）：
│   ├── Zone 是"事件区间"，不是"滑动窗口"
│   ├── 一旦进入 exhaustion（score > threshold）：
│   │   zone_start = t  ← 冻结起点
│   │   zone_high_close = max(close[zone_start : t])  ← 累积更新
│   │   zone_low = min(low[zone_start : t])            ← 累积更新
│   ├── 一旦 exhaustion 结束（score ≤ threshold）：
│   │   zone 闭合，zone_high_close / zone_low 锁死，不再更新

│   │
```

### 1.3 Exhaustion Score 评分模型（核心）

```
exhaustion_score = w1 × 趋势强度 + w2 × 成交量异常 + w3 × 波动扩张 + w4 × 位置约束

判定：exhaustion_score > threshold → 进入 Exhaustion Zone
```

#### 1.3.1 评分项定义

**C1：趋势强度（双模式，max 聚合）**

```
C1 = max(
  过去 60 日收盘跌幅 / X_60,   ← 慢熊模式
  过去 3 日收盘跌幅 / X_3       ← 急崩模式
)
目的：覆盖 2018（慢熊16%）和 2022-11（急崩，20日跌幅仅 -2.6%）

X_60 待定（第二组参数，从 P0 锚点反推）
X_3  待定（第二组参数，从 P0 锚点反推）
```

**C2：新低突破（硬条件，不在评分模型内）**

```
条件：当日 low < 过去 252 日最低 low（一年新低标准）
作用：必须先满足 C2，才启动 exhaustion 评分计算
C2 不参与评分，是进入 exhaustion 计算的前置硬条件
```

**C3：成交量异常（多日聚合，max 聚合）**

```
C3 = max(
  当日 volume / 20日均量 / V,      ← 单日量比
  3日累计 volume / (3×20日均量) / V  ← 3日累计量比
) / V

V 待定（第二组参数，从 P0 锚点反推）
```

**C4：波动扩张（多日聚合，max 聚合）**

```
C4 = max(
  当日 (high - low) / ATR_14 / A,    ← 单日宽幅
  3日累计 (high - low) / ATR_14 / A   ← 3日累计宽幅
) / A

A 待定（第二组参数，从 P0 锚点反推）
```

**C5：位置约束（降级为评分项，不再硬条件）**

```
C5 = 0.5 × 回撤比例得分 + 0.5 × swing_low 偏差得分

回撤比例得分 = min(1.0, 从60日高点回撤比例 / R)
  R 待定（第三组参数，用误报率校准）

swing_low 偏差得分 = max(0, 1.0 - |当前low - swing_low| / swing_low / B)
  swing_low 识别：固定窗口分形，window=10（见 D-004）
  B 待定（第三组参数，用误报率校准）
```

#### 1.3.2 权重与阈值

```
weight 方向（固定，不作为调优参数）：
├── w1 = 0.35（趋势强度：最重要，没有趋势就没有积累，SC 存在的前提）
├── w2 = 0.25（成交量异常：供应高潮的标志）
├── w3 = 0.25（波动扩张：气候性行动的确认）
└── w4 = 0.15（位置约束：过滤器，不是信号源，降权防止过约束）

threshold 方向（唯一调节旋钮）：
├── 搜索范围：threshold ∈ [0.5 ~ 0.7]
├── 初始设定：threshold = 0.6
├── 含义：不需要所有条件都完美满足，总分及格即可
└── 调优策略：先用 0.6 跑全量回测，看检出分布（目标 1~3次/年），
    过多则提 threshold，过少则降 threshold

核心原则（防过拟合）：
├── 权重固定不动 → 4个P0样本无法支撑5维参数空间
├── threshold 单参数调节 → 从"参数拟合"变为"模型结构验证"
└── 若 threshold 降到 0.5 还是漏 P0 锚点 → 模型结构有问题，不是参数问题
```

### 1.4 最终 SC 判定流程（V8.3 最终版：zone 冻结 + 双通道确认）

```
对日线每根K线，按序执行：

Step 0：前置硬条件
  if 当日 low >= 过去 252 日最低 low:
    → 不进入 exhaustion 计算，跳过

Step 1：Exhaustion 评分（C1/C3/C4/C5）
  exhaustion_score = w1×C1 + w2×C3 + w3×C4 + w4×C5
  if exhaustion_score < threshold:
    if zone 处于活跃状态:
      → zone 闭合，zone_high_close / zone_low 锁死
    → 跳过

Step 2：Zone 生命周期管理（🔴 冻结规则）
  if zone 未激活 AND exhaustion_score ≥ threshold:
    → zone_start = t（冻结起点）
    → zone_high_close = close[t]
    → zone_low = low[t]
    → zone 状态 = 活跃

  if zone 已激活 AND exhaustion_score ≥ threshold:
    → zone_high_close = max(zone_high_close, close[t])  ← 累积更新
    → zone_low = min(zone_low, low[t])                  ← 累积更新
    → zone 持续延伸（最大 5 日）

Step 3：Zone 闭合
  if zone 已激活 AND exhaustion_score < threshold:
    → zone 闭合，zone_high_close / zone_low 锁死
    → zone 不再接受新K线，等待 confirmation

Step 4：Confirmation 判定（🔴 双通道）
  if zone 已闭合（锁死状态）:
    对之后每根K线检查：
    
    strong_confirm = close > zone_high_close AND close_pct > 0.025
    weak_confirm   = close > zone_high_close AND close > open
    
    if strong_confirm OR weak_confirm:
      → SC 确认！记录 SC 日期 = confirm_bar 日期
      → SC 低点 = zone_low（已锁死）
      → zone 生命周期结束（去重：同一 zone 只确认一次）
      → confirm 类型标记：strong / weak（用于后续分析）

Step 5：超时处理
  if zone 闭合后 10 日内无 confirm:
    → zone 作废，视为"假 exhaustion"
    → 等待下一个 C2 触发重新开始
  if exhaustion_zone 闭合后 10 日内无 confirm_bar:
    → zone 作废，视为"假 exhaustion"
    → 等待下一个 C2 触发重新开始
```

**SC 类型标记**（用于后续分析，不影响判定逻辑）:

| 类型 | 特征 | 例子 |
|------|------|------|
| 慢速耗尽型 | zone ≥ 3 日，无极端量/宽幅 | 2018-12 |
| 恐慌释放型 | zone 1-2 日，量比 > 2x | 2020-03, 2022-11 |
| 标准耗尽型 | zone 1-3 日，量比 1.5-3x | 2022-06 |

### 1.5 BC 识别（对称设计，方向相反）

BC 的两阶段模型与 SC 对称，方向相反：

```
阶段1：Euphoria Zone（狂热区）
├── C1：过去60日涨幅 > X% OR 过去3日涨幅 > Y%
├── C2：当日 high > 过去252日最高 high（硬条件）
├── C3/C4：成交量/宽幅条件同 SC（方向相反）
├── C5：当前价格 > 60日最低点 × (1+R%)
└── 输出：zone_high（狂热区最高点）、zone_low_close（狂热区最低收盘价）

阶段2：Distribution Confirmation Bar（派发确认K）
├── close < zone_low_close（收盘价跌破狂热区最低收盘价）
└── AND close_pct < -2.5%（价格动量确认，对称 SC）
```

BC 参数在 SC 参数校准完成后用对称值填入，不独立校准。BC 锚点（2021-11 高点、2022-03 反弹顶）用于单独验证。

```

TR Low  = SC 低点 × 0.995（V8.3：SC 低点 = exhaustion_zone 最低点，0.995 留缓冲带）
TR Height = TR High - TR Low

├── Phase B/C/D/E 期间 TR 边界不重新计算

├── Phase C Spring 跌破 TR Low 是被允许的（Spring 定义的一部分）

```

## 阶段回溯：从退出机制到指标定义溯源（2026-05-07）

### 背景

V8 退出机制优化尝试了三个方向，全部受阻。根本原因不在退出逻辑本身，而在上游信号和过滤器定义——每个指标在定义时都隐含了假设，当这些假设相互冲突时，下游优化无从下手。

---

### 实验记录

#### 实验 1：down_wave 退出时机诊断

**脚本**: `analyze_down_wave_exit_timing.py`  
**数据**: 199 笔 axis_support + down_wave 退出

| 指标 | 值 |
|------|-----|
| 退出后 10 根K线下跌比例 | **77.9%** |
| 退出后上涨比例 | 22.1% |

**结论**: down_wave 方向判断正确（78% 胜率），问题不在退出逻辑本身，而在退出时机太早（中位数 +1.43%）。

#### 实验 2：MIN_PROFIT 利润门槛

**改动**: 在 `custom_exit` 中加 `current_profit >= WY_DW_MIN_PROFIT` 门控  
**测试值**: 0.0（基线）/ 0.02 / 0.03

**结果**: 三次回测数据几乎无差异。  
**根因**: down_wave 同时存在于两条路径——`exit_signal`（向量化，line 3674）和 `custom_exit`（逐笔，line 5878）。Freqtrade 先检查 `exit_signal`，触发即退出，`custom_exit` 的利润门控永远等不到。

**结论**: 信号路径无法承载 per-trade 条件。利润门槛方案被否决。

#### 实验 3：Phase D 与 wave_start 关系诊断

**脚本**: `diagnose_wave_start_phase.py`  
**假设**: 日线 Phase D 上下文可提升 wave_start 入场频率（从 ~36笔/年 → ~55笔/年）

**发现**:

| Phase | 天数 | 占比 | wave_start 笔数 |
|-------|------|------|:---:|
| A | 11 | 0.5% | 0 |
| B | 144 | 5.9% | 0 |
| C | **0** | **0.0%** | **0** |
| D | 90 | 3.7% | 1 |
| E | 1208 | 49.8% | 133 |
| unknown | 975 | 40.2% | 7 |

**结论**: Phase D 仅占 3.7% 时间窗，天花板太低。Phase C 从未触发（Spring 条件太苛刻）。94% 的 wave_start 已在 Phase E 中，瓶颈不在 Phase。

#### 实验 4：Phase 检测器参数调优

**改动**: `phase_detector.py`
- `spring_max_days`: 3 → 7
- B→D 量能门槛: 1.2x → 移除
- C→D 量能门槛: 1.5x → 移除
- E→D 确认天数: 2 → 1

**结果**:

| 指标 | 改前 | 改后 |
|------|------|------|
| Phase D 天数 | 90 (3.7%) | 127 (5.2%) |
| Phase C 天数 | 0 | 0 |
| Phase D wave_start | 1 笔 | 2 笔 |

**结论**: 参数调整后 Phase D 增长 41%，但对 wave_start 增量贡献仅 +1 笔。Phase 状态机本身的结构性限制（TR 锁定、E→D 回退难、C 从不触发）比参数更根本。

#### 实验 5：wave_start 过滤器漏斗分析

**脚本**: 策略内嵌计数器，输出到 `ws_filter_diag.txt`  
**方法**: 对 wave_start_entry 的 6 个条件逐级计数拦截数

```
漏斗: raw=709 → final=244 (通过率 34.4%)
```

| 过滤器 | 拦截数 | 拦截率 |
|--------|:---:|:---:|
| raw 信号 | 709 | - |
| ❌ **bull_market** (close>ema200) | **465** | **65.6%** |
| wyckoff_context_ok | 0 | 0% |
| harmony_ok | 0 | 0% |
| no_sot_warning | 0 | 0% |
| quality_ok | 0 | 0% |
| ✅ final | 244 | 34.4% |

**发现**: `bull_market` 一个条件拦截了 65.6% 的信号。其他四个 Wyckoff 条件拦截率全为 0——一旦过 EMA200，全过。EMA200 是静态滞后指标，正在物理性地阉割 wave_start 的因果发现能力。

#### 实验 6：移除 bull_market（wave_start 专用）

**改动**: `wave_start_entry` 移除 `bull_market` 条件，依赖 V8 Phase 过滤器（C/D/E）兜底

经过 6 个实验、3 个方向的尝试，一个共同的模式浮现：

