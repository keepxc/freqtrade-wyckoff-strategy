# Signal Ecosystem Diagnostic Prompt

## 任务目标
你是一个策略诊断专家。请基于 P5 数据库中的事实数据，对信号生态进行全景诊断，识别：
1. 信号质量分布与漂移
2. 拒绝原因瓶颈
3. 相位效率差异
4. Regime 适配问题
5. 潜在优化方向

## 输入数据源
你将获得以下数据摘要（由脚本从 SQLite 提取）：

### 1. 信号质量分布
- `signal_quality_before` 和 `signal_quality_after` 的分布
- 不同质量区间的执行率和最终盈亏
- 质量阈值卡点分析

### 2. 拒绝原因统计
- `rejection_reason` 频率排名
- 各拒绝原因对应的信号质量分布
- 哪些拒绝是"正确防守"，哪些是"过度保守"

### 3. 相位效率对比
- 不同 `phase_context_tag` 下的：
  - 信号生成数
  - 执行率
  - 胜率
  - 平均收益
- Phase C vs Phase D vs Phase E 的表现差异

### 4. Enter Tag × Regime 交叉分析
- 不同 `enter_tag` 在不同 `macro_phase_enter` / `market_env_enter` 下的表现
- 识别"标签-环境不匹配"

### 5. 时间窗口漂移
- 最近 N 条信号的质量均值 vs 历史基线
- 最近窗口的胜率 / 平均收益 vs 基线窗口
- 是否存在系统性漂移

## 诊断框架

### A. 信号质量诊断
**关键问题：**
- 当前信号质量分布是否健康？
- `signal_quality_after` > 1.0 的信号占比多少？执行率如何？
- 质量在 0.8-1.0 区间的信号是否被过度拒绝？
- 质量 > 1.2 的高质量信号最终盈亏是否显著优于低质量信号？

**输出要求：**
- 质量分布直方图描述（0-0.5, 0.5-0.8, 0.8-1.0, 1.0-1.2, >1.2）
- 各区间的执行率、胜率、平均收益
- 识别"高质量但未执行"和"低质量但执行了"的异常样本

---

### B. 拒绝原因诊断
**关键问题：**
- 哪个拒绝原因卡得最死？
- `regime_blocked` 是否过于频繁？
- `rr_blocked` 是否合理？被拒绝的信号事后表现如何？
- `max_open_trades_blocked` 是否暗示仓位管理过于保守？

**输出要求：**
- 拒绝原因排名（频率 + 占比）
- 每个拒绝原因对应的信号质量中位数
- 建议：哪些拒绝规则可以放宽？哪些需要收紧？

---

### C. 相位效率诊断
**关键问题：**
- Phase C / D / E 哪个阶段信号最多？哪个阶段表现最好？
- Phase C 的信号是否过早？Phase E 的信号是否过晚？
- 不同 phase 的执行率差异是否合理？

**输出要求：**
- 各 phase 的信号数、执行率、胜率、平均收益对比表
- 识别"高频低效"和"低频高效"的 phase
- 建议：是否需要调整某些 phase 的信号生成条件或授权规则？

---

### D. Regime 适配诊断
**关键问题：**
- 哪些 `enter_tag` 在哪些 `macro_phase` 下表现最好/最差？
- 是否存在"标签-环境错配"（例如 spring 在 markdown 中表现差）？
- `bear_market_mode` 开启时，信号质量和胜率是否显著下降？

**输出要求：**
- Enter Tag × Macro Phase 热力图（胜率或平均收益）
- 识别 3-5 个"高风险组合"（样本 ≥5 且胜率 <40% 或平均收益 <-1%）
- 建议：是否需要在特定 regime 下禁用某些 enter_tag？

---

### E. 漂移初筛诊断
**关键问题：**
- 最近 N 条信号的质量均值是否低于历史基线？
- 最近窗口的胜率 / 平均收益是否显著下降？
- 是否存在某个 detector / regime 标签的分布突变？

**输出要求：**
- 最近窗口 vs 基线窗口的关键指标对比表
- 识别是否存在系统性漂移（胜率下降 >10%，或平均收益下降 >0.5%）
- 建议：是否需要触发 drift alert 或启动参数回滚？

---

## 输出格式要求

### 1. 执行摘要（Executive Summary）
- 3-5 句话总结当前信号生态的整体健康度
- 列出 1-3 个最紧急的问题

### 2. 分项诊断
按 A/B/C/D/E 五个维度分别输出：
- 数据事实
- 诊断结论
- 风险等级（低/中/高）
- 建议行动

### 3. 优先级排序
列出 Top 3 优化方向，按预期收益 × 实施难度排序

### 4. 样本充分性声明
明确说明：
- 本次分析覆盖的时间范围
- 总信号数 / 已平仓交易数
- 是否存在样本不足的维度（<10 笔）

---

## 约束与原则

### 数据诚实原则
- 如果某个维度样本 <10，必须标注"样本不足，结论不可靠"
- 不要过度解读噪声
- 区分"统计显著"和"实际显著"

### 可操作性原则
- 每个诊断结论必须对应至少一个可执行的建议
- 建议必须具体（例如"建议将 rr_threshold 从 1.5 降至 1.3"，而非"建议优化 RR 规则"）

### 风险意识原则
- 优先识别"高频低效"问题（影响面大）
- 对"低频高效"保持谨慎（可能是噪声）
- 明确区分"需要立即修复"和"可以观察"

## 示例输出片段

### 执行摘要
> 当前信号生态整体健康度：**中等偏弱**。主要问题：
> 1. **拒绝过度保守**：`rr_blocked` 占拒绝原因 42%，但被拒绝信号的质量中位数为 1.05，事后胜率 52%，暗示 RR 阈值过高。
> 2. **Phase E 低效**：Phase E 信号占比 18%，但胜率仅 38%，平均收益 -0.8%，建议收紧 Phase E 授权条件。
> 3. **Spring 在 Markdown 错配**：`wyckoff_spring` 在 `macro_phase=markdown` 下胜率 32%（样本 15 笔），显著低于 markup 下的 58%。

### 分项诊断示例（B. 拒绝原因）
**数据事实：**
- 总候选信号：1,247 条
- 已执行：312 条（25%）
- 拒绝原因排名：
  1. `rr_blocked`: 524 条（42%）
  2. `regime_blocked`: 287 条（23%）
  3. `quality_below_threshold`: 124 条（10%）

**诊断结论：**
- `rr_blocked` 是最大瓶颈，且被拒绝信号的质量中位数为 1.05，事后模拟胜率 52%，暗示 RR 阈值（当前 1.5）过于保守。
- `regime_blocked` 占比偏高，需进一步分析是否 P2 regime 判定过于严格。

**风险等级：** 中

**建议行动：**
1. 将 `rr_long_threshold` 从 1.5 降至 1.3，预期可释放约 200 条信号
2. 对 `regime_blocked` 信号做事后回测，验证 regime 规则是否过度防守

## 使用方式
1. 运行数据提取脚本，生成 JSON 摘要文件
2. 将 JSON 摘要 + 本 prompt 一起提交给 AI
3. AI 输出诊断报告（markdown 格式）
4. 人工审核 + 决策是否启动实验

## 附录：关键指标定义

- **信号质量（signal_quality）**：策略内部计算的信号评分，通常 >1.0 为合格
- **执行率（execution_rate）**：已执行信号数 / 总候选信号数
- **胜率（win_rate）**：盈利交易数 / 总已平仓交易数
- **平均收益（avg_pnl）**：所有已平仓交易的 `profit_pct` 均值
- **Profit Factor（PF）**：总盈利 / 总亏损（绝对值）
- **Phase Context**：Wyckoff 相位标签（phase_a/b/c/d/e）
- **Macro Phase**：宏观趋势标签（accumulation/markup/distribution/markdown/transition）
