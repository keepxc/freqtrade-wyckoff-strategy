# 协议修订 · 2026-09-28（二）— 提示词 v2 + 调用参数

> `FORWARD_PROTOCOL.md` 的判据（期限 7d/30d、基准 55%、n≥30、Wilson 下界、检查点 90%/90%、
> 去重规则）**一字未改**。本修订记录的是**前提条件变更**：AI 被问的问题变了，
> 按协议 §5，变更前后样本不得混池。决策点均经用户确认（2026-09-28）。

## 1. 变更内容

| 项 | v1 | v2（`PROMPT_VERSION = "v2-20260928"`） | 为什么 |
|---|---|---|---|
| 方向定义 | 未定义，AI 自行理解 | 多 = P(N 天后收盘 > 当前收盘) > 55%；空 < 45%；中性 45~55% | 与 score.py 的兑现口径逐字对齐；防止 AI 用「当前趋势」代替「接下来去哪」 |
| 看哪一栏 | 未指定 | 7 天以下栏 4H 为主（日线只作背景）；30 天以上栏日线为主 | 避免依据在两栏间漂移；AI 7 天看 4H 也使其与程序（θ=30% 日线级结构）保持独立 |
| 输出末行 | `{"dir_7d","dir_30d"}` | 追加 `"p_up_7d": 0~100 整数` | 辅助记录，用于 ④ 校准（Brier），**不进任何判据** |
| 问题范围 | 含「操作建议框架」「3 个月」 | 删除；正文 ≤ 300 字 | 不参与打分；长回答在 max_tokens 下易截断末行 |
| 未收盘 K 线 | 未说明 | 明示两栏最右一根未走完 | 防止把残缺 K 线当完整结构 |
| 温度 | 未设（免费模型默认约 1） | `temperature = 0` | 密集层测「AI 翻转率」，默认温度下翻转大半是抽样噪声 |
| 截断 | 未检测 | `finish_reason == "length"` → 算调用失败、换候选；字段落盘 | 截断不能被记成「AI 没按格式输出」 |
| 4H 横轴 | 按月打点（仅 3 个标签） | 按 ISO 周打点 | AI 需数清最近几天；数据不变，只改标注 |

## 2. 解析与判据的边界

- `ai_parse_ok`（冻结的检查点判据）**仍只按 `dir_7d` / `dir_30d` 判定**。`p_up_7d` 缺失或越界只置空，不算解析失败——否则等于改了检查点判据。
- `ai_p_consistent`：概率与方向是否符合定义，仅描述性记录。

## 3. 样本处置（用户确认）

- 现有正式样本 `20260928_asia`（v1）**标注后不计入 n**：`score.py` 只统计
  `prompt_version == v2-20260928` 的行，报告首部写明排除行数。
- 两周管线检查点窗口从**首条 v2 记录**起算。
- `dense_log.csv` 同样带 `prompt_version`，分析时按版本分组。

## 4. 运维

- cron 三行统一加 `flock -w 900 .run.lock`：样本层与密集层共用 `data/`、`chart_dual.png`、
  `watch_latest.json`，防止并发互相覆盖；排队最多 15 分钟，不丢轮次。
  **部署后需重跑 `./install_cron.sh`** 使其生效。

## 5. 以后再改提示词

改 `ask_ai.py` 里 `PROMPT_*` 的任何一个字 → 升 `PROMPT_VERSION` → 补一份本类修订。不升版本号的提示词改动视为违规。
