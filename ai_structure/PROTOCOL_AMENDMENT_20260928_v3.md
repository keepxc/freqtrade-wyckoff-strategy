# 协议修订 · 2026-09-28（三）— 失败后「再识别一次」

> `FORWARD_PROTOCOL.md` 的判据常量、期限、基准率、去重规则**一字未改**。
> 本修订记录的是**交付策略**的变更，以及它对冻结判据「AI 结构化解析成功率 ≥90%」的**含义影响**。

## 1. 起因

- `20260928_dense_12`：HTTP 200、非空、`finish_reason=stop`，**但末行是「多 60」**，没有 `DIRECTION_JSON`
  → 旧逻辑直接落进日志记成解析失败（`ai_parse_ok=0`）。
- 同日 `20260928_euus` 槽：主候选 `nemotron` 返回**无 `choices` 的错误体**，由备胎 `dots-3` 兜住。
- 用户指令（2026-09-28）：**「后续这种情况，都再识别一次。」**

## 2. 触发条件（任一即「这次回复不能用」→ 换候选 → 不够就再识别一轮）

| 条件 | 代码标记 | 说明 |
|---|---|---|
| HTTP ≠ 200 | `http` | 含 429 / 5xx |
| 响应里没有 `choices` | `struct` | 上游把错误体当 200 返回 |
| 回复为空 | `empty` | 推理 token 吃光预算 |
| `finish_reason == length` | `trunc` | 被 `max_tokens` 截断，末行大概率丢了 |
| **末行无合规 `DIRECTION_JSON`** | `format` | **本次新增**——模型没守格式 |

## 3. 上限

- `VISION_TRIES`（默认 **2**）= 轮数上限；每轮按候选列表顺序遍历。
- 总调用次数 = 候选数 × 轮数；两轮都不合规 → **照旧记失败，不会无限试**。
- 设为 `VISION_TRIES=1` 即退回「不重试」的旧行为。

## 4. 对检查点判据的影响（必须知道）

- `ai_parse_ok`（冻结判据之一）含义由「**首次回复**是否合规」变为「**重试后交付结果**是否合规」。
- 为保住可测性，新增两列（描述性，不参与判据）：
  - `ai_first_parse_ok`：首轮是否一次就对
  - `ai_attempts`：本次共调用几次
- **报告口径**：检查点照旧按 `ai_parse_ok` 计算；**但 14 天报告必须同时给出首轮合规率**
  （`ai_first_parse_ok` 的比例）。两者差距大 ⇒ 结论是「模型不守格式、靠重试兜」，
  **不是**「管线健康」。
- 若首轮合规率长期 < 90%：那是**模型选型问题**，处置是换候选（并再开一份本类修订），
  而不是继续用重试掩盖。

## 7. 补丁（同日）：首轮口径拆分 + 逐次明细落盘

**问题（本修订原版的测量缺陷）**：
- `ai_first_parse_ok` 取的是**第一次调用**是否合规。euus 槽那种「主候选返回无 `choices` 错误体」是
  **上游故障**，却会被记成「首轮不合规」，§4 的「首轮合规率 < 90% ⇒ 模型选型问题」会被误触发。
- 全部尝试都失败时 `ask_vision.py` 直接退出，`attempts` 明细**没有落到任何文件**——恰恰是最需要看的情况。

**修复**（判据常量、提示词、`ai_parse_ok` 口径均不变）：

| 新字段 | 含义 |
|---|---|
| `ai_first_fail` | 第一次调用的失败类型（`http/struct/empty/trunc/format`），首次成功为空 |
| `ai_first_resp_ok` | **首个模型真正作答**（排除 `http/struct`）的尝试是否合规；全程只有上游故障时为空（不可判定，不进分母） |
| `out/ai_attempts.jsonl` | 每次调用一行（成功/失败都记，追加）：`run_key/slot/model/round/note/http_status/elapsed_s/prompt_version` |

**§4 报告口径据此修正**：判「模型守不守格式」用 `ai_first_resp_ok` 的比例；`ai_first_parse_ok`
保留（= 一次就交付的比例，含上游故障），两者之差即上游故障造成的首轮损耗。

**候选顺序回看规则（2026-09-28 用户确认，数据前冻结）**：
- 不做单独的候选 A/B（温度 0 下重复同图只测稳定性、不测准确性；5 次样本的置信区间过宽；
  集中调用只采一个时间窗且可能自触发限流）。
- 以 `ai_attempts.jsonl` 为数据源，**每个候选累计 ≥30 次调用**后回看一次，按
  ①可用率（非 `http/struct`）②格式合规率（非 `http/struct` 中 `note=ok` 的比例）排定顺序。
- 当前顺序为 v4（`403c969`，2026-09-28 22:51 +0800）定的 dots-3 → nemotron；**计数从 v4 变更时点起算**，
  v4 之前的调用不混池。v4 本身依据的是 n=4~8 的单日观测，属临时排序，由本回看规则接管复核。
- 回看前不再改顺序（故障应急除外，须记录时点）。若回看后调整，须另开一份修订并记录变更时点，
  **变更前后样本不混池统计**。
- 次序效应：第一顺位候选的调用次数天然远多于备胎，备胎可能长期凑不满 30 次——此时只对达标的候选下结论，
  不得用备胎的小样本与首位比较。
